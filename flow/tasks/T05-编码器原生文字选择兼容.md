# T05 · 编码器原生文字选择兼容

> 本任务卡记录 Maker 固件对 EasyInput App 编码器文字选择配置的兼容合同与软件侧验收。实现、宿主回归和 ESP-IDF 构建已完成；重新同步 App 配置与实板文字选择仍需独立验证。

- **背景**：EasyInput App 会把编码器设置为 `cursor` 模式，并把按压动作同步为 `text_caret_select`。旧 Maker 固件无法识别该动作，导致整份配置以 `unknown_action` 被拒绝；把编码器改成普通滚动后可以同步，说明故障位于动作语义缺失，不是 BLE、配置接收或 Host Action 通道。
- **目标**：在不修改 App、GPIO、BOOT、GPIO8、电源、分区、设备身份、Host Action 协议或默认编码器动作的前提下，让 Maker 完整支持原生键盘文字选择。
- **产出路径**：配置与纯逻辑位于 `components/keyboard/`，固件编排与 USB/BLE 键盘发送位于 `main/`，宿主验证位于 `host_test/`。
- **状态**：软件侧完成。仅含本功能的 Git 暂存快照已独立完成定向测试 6/6、完整宿主测试 56/56，以及 ESP-IDF 5.5.5 的 `v2` / `esp32s3` 默认构建；未烧录本次镜像，未重新同步 App 配置，未在真实应用中观察文字选择。含其他未提交功能的完整工作区曾为 58/58，但不作为本原子提交的通过证据。

## 固定行为合同

### 配置兼容

- 规范动作名为 `text_caret_select`；旧名称 `mouse_drag_select` 继续兼容，并解析为同一个内部动作。
- 该动作只能配置给编码器按压位，且编码器旋转模式必须为 `cursor`。
- 把该动作配置给 KEY1—KEY8、使用非 `cursor` 模式或提供未知动作时，整份候选配置按现有规则拒绝，不保存、不替换当前运行配置。
- 默认编码器按压动作仍为 `scroll_axis_toggle`，本功能不会写入默认 Keymap。

### 操作语义

- 第一次短按并松开编码器：进入文字选择状态，本次按压本身不发送键盘报告。
- 选择状态中旋转一个刻度：顺时针发送一次完整 `Shift+ArrowRight`，逆时针发送一次完整 `Shift+ArrowLeft`。
- 第二次短按并松开编码器：退出文字选择状态；电脑中已经选中的文字保持不变。
- 按住编码器 3 秒：继续进入既有系统配置模式，同时退出文字选择；长按后的松开不再被解释为短按切换。

### 传输与状态保护

- 文字选择使用标准键盘 HID，不新增鼠标拖拽、App Command、Report ID 或私有协议。
- 合成的 Shift+方向键复用当前真实键盘快照，不覆盖用户已经按住的修饰键或其他按键。
- USB 绑定当前 endpoint epoch，BLE 绑定当前 `{handle, generation}` owner；连接所有权变化时不把旧刻度转交给新主机。
- 每个刻度的按下与松开按顺序排队；队列忙时保留待处理距离，不静默丢失、乱序或越过退出边界。
