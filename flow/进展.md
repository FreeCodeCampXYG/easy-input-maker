## 2026-09-02 · 钢琴/鼓机槽隔离 Host Action · Codex
- 根因：音频初始化、请求或入队失败返回 `false` 后，实体键事件回落到第一槽 Keymap，导致“打开应用”仍触发。
- 修复：音乐/鼓机槽无条件消费 KEY1—KEY8；切槽前清理 HeldKeyboard、键盘快照和 bridged hotkey 状态。
- 验证：完整宿主 CTest 66/66 通过；未推送或烧录。若仍出现切槽后迟到打开应用，下一步只针对 USB/BLE FIFO 中已排队 Host Action 做 epoch 取消，不能清空全部 AppCommand。

## 2026-09-02 · USB HID 对齐与固定资源审计 · Codex
- 根因：`SEQ1/0x17` 曾错误插入键盘 LED 的 5-bit Output 与 3-bit 填充之间，导致键盘和 Vendor Output 均非字节对齐，Windows 拒绝枚举。
- 修复：恢复键盘 `5+3=8 bit` 对齐；将 `SEQ1` 的 63-byte Feature/Output 移至 Vendor Collection；补齐 `0x13` 的 16-byte Output；BLE 控制写入改为固定 63-byte 缓冲。
- 验证：宿主 CTest 65/65、ESP-IDF 5.5.5 / ESP32-S3 构建、`git diff --check` 均通过；镜像 `0x194190`，App 分区余量 47%。
- 未验证：Windows 正常枚举、Studio `MUS1/SEQ1` 实际写入、TinyUSB 鼠标宏位账本覆盖和音频采集长时栈高水位。

## 2026-09-02 · 旋钮切换失效诊断与修复 · Codex
- 根因：设备已有 NVS 配置时不会使用新的 `DefaultKeymap`；旧 `settings`/`scroll_axis_toggle` 按压动作绕过环形入口，且启动音乐开关与环形索引可能错位。
- 修复：默认从键盘槽启动；兼容旧按压动作迁移到 `function_cycle`；鼓模式非鼓键事件保持在音乐路径内，不再回落为普通键盘动作。
- 验证：宿主 CTest 65/65 通过，`git diff --check` 通过；ESP-IDF 和实板切换待验证。

## 2026-09-02 · 修复外部诊断状态请求报告类型 · Codex
- 做了什么：将 USB Vendor 状态请求 `0x13` 从 Feature Report 改为 16 字节 Output Report，回调同时接受两种类型。
- 问题→根因：Flasher 使用的 Go HID 库只能发送 Output Report，Feature 请求没有真正触发 Maker 的状态回调。
- 怎么理解：状态响应格式和 512 字节预算不变；必须烧录包含此修复的新固件，旧固件仍无法被当前 Flasher 自动读取。
- 验证：`config_status_tests`、`status_hid_protocol_tests` 通过；实板 HID 回报待验证。

## 2026-09-01 · Vendor HID 诊断请求标志 · Codex
- 做了什么：在既有 16 字节状态请求中增加 `diagnostics` 标志；请求带标志时返回详细 `diag` 遥测，供外部烧录器读取最近输入和旋钮计数。
- 为什么这么做：普通状态响应可能因音频字段触发 512 字节压缩，省略详细诊断；增加 1 bit 可保持协议和容量不变。
- 验证：`config_status_tests`、`status_hid_protocol_tests` 通过；ESP-IDF 构建/实板 HID 回报待验证。
