## 2026-08-22 · Maker 编码器原生文字选择软件侧完成 · Codex
- 做了什么：先用对照现象确认只有编码器 `cursor + text_caret_select` 配置会被 `unknown_action` 拒绝，再按现有 EasyInput 配置合同补宿主红测和完整实现。Maker 现在兼容规范名称与旧名称，短按切换文字选择，旋转发送标准键盘 Shift+左右方向键，3 秒长按保留既有系统配置语义；同时加入队列背压、真实键盘快照和 USB/BLE 连接 owner 保护。未修改 App、Host Action 协议、硬件配置、分区或设备身份，未烧录。
- 为什么这么做：普通滚动配置能够同步，已经排除 BLE 连接、配置接收和 Host Action 通道；缺口是 Maker 没有实现 App 已发送的编码器文字选择动作，补齐完整语义才能让新手按教程同步整份配置，而不是绕开该动作。
- 怎么理解：第一次短按进入选择，顺／逆时针分别产生完整 `Shift+ArrowRight/Left`，第二次短按退出；默认仍是 `scroll_axis_toggle`。旧名称只作为兼容入口，不产生另一套行为。
- 产出（路径）：任务合同与验收位于 `flow/tasks/T05-编码器原生文字选择兼容.md`；实现位于 `components/keyboard/` 与 `main/`，宿主测试位于 `host_test/`。
- 测试与构建：实现前 CMake 因缺少 `encoder_press_gesture.cpp` 产生真实红灯；随后从 Git 暂存区导出仅含编码器改动的隔离快照，定向 6/6、完整宿主 56/56 通过。该快照用 ESP-IDF 5.5.5 对 `v2` / `esp32s3` 默认构建成功，应用镜像为 `0x18fd00` 字节，3 MiB App 分区剩余 `0x170300` 字节（48%）；未暂存的 Host Action 改动没有参与，`git diff --cached --check` 通过。
- 问题→解决：源码契约测试最初仍查找旧的 `void handle_input_event`，而新实现需要 `bool` 返回值表达队列是否接收；同步测试合同后定向回归全部通过。
- 下一步：先用 EasyInput App 重新同步原先失败的 `cursor + text_caret_select` 配置并观察成功确认；只有需要验证板上行为时，再单独确认是否烧录当前新镜像。构建成功不能替代这两项证据。
