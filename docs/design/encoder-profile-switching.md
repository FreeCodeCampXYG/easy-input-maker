# 旋钮按压切换设备配置设计

## 目标

让用户只通过右侧旋钮完成常用配置切换，不必每次回到桌面应用；保留现有旋钮旋转、短按配置和长按配置入口的兼容行为。

本设计针对 EasyInput V2.0 / ESP32-S3。编码器 A/B/按压固定为 GPIO `17/16/18`，按压输入必须继续走现有去抖与短按/长按手势状态机。

## 当前基线与缺口

- 旋钮短按当前由 `dispatch_encoder_press_click()` 处理，默认动作是切换滚动轴。
- `toggle_profile`、`previous_profile`、`next_profile` 当前会生成桌面端 App Command，并不在固件内加载另一份配置。
- 配置接收链路当前把一份 JSON 应用到 `ConfigState`，并保存为单份配置；没有设备端 profile 槽位、活动槽位和回滚记录。
- 音乐配置 `MUS1` 使用独立的 `music_v1` NVS，不应被普通键盘 profile 覆盖或清空。

本轮已先落地“环形索引”最小实现：默认旋钮动作改为 `function_cycle`，宿主侧用通用 `EncoderFunctionRing` 做首尾相接；带扬声器固件的运行槽位暂为“键盘 → 音乐”，无扬声器构建保持单槽兼容。

## 推荐交互

### 旋钮动作

| 动作 | 行为 | 反馈 |
| --- | --- | --- |
| 短按一次 | 切换到下一个已启用的本地 profile；循环到末尾后回到第一个 | LED 显示槽位颜色/短脉冲；状态报告带 `active_profile` |
| 旋转 | 继续使用当前 profile 的旋转设置；音乐 profile 下继续调音量 | 沿用现有方向反馈 |
| 按住约 3 秒 | 进入现有配置模式，不切换 profile | 沿用现有 ConfigMode 反馈 |
| 短按后 1 秒内再次短按 | 仍按一次一次切换，不增加二击特殊语义 | 防止误触发隐藏功能 |

短按切换只在“已确认的新 profile 已生效”后更新活动槽位；加载失败时保留旧配置和旧槽位，并给出错误闪烁。这样不会因为坏配置导致键盘失控。

### 默认槽位

首版建议固定 4 个槽位，槽位名由桌面端写入但设备端只保存脱敏短名（最多 12 个 UTF-8 字节）：

1. `日常`：当前桌面键盘配置。
2. `写作`：常用编辑快捷键/文本动作。
3. `音乐`：键盘按键映射到钢琴，旋钮调音量；音乐参数继续走 `music_v1`。
4. `备用`：恢复或临时实验配置。

没有配置的槽位不参与循环。若只存在一个槽位，短按不改变配置，只给确认反馈。

## 数据与持久化

建议新增独立 NVS 命名空间 `profiles_v1`，不要改写现有单配置键和 `music_v1`：

- `slot_0` … `slot_3`：经过 JSON 长度、字段和动作校验的完整 profile 文本。
- `slot_meta`：启用位图、短名、版本号和每槽 CRC32。
- `active_slot`：最后一次成功应用的槽位。
- `pending_slot`：切换过程中暂存的目标槽位；启动时若发现未完成切换，回滚到 `active_slot`。

关键控制点：先解析并校验目标 profile，再原子写入 `slot_n` 与 CRC，最后提交 `active_slot`；任何一步失败都保留旧槽位和旧配置，避免断电或坏包把设备留在半配置状态。

## 与桌面端同步的边界

首版不改变现有 `S3C` 分片协议的魔数、版本、CRC 或 63 字节报告容量。桌面端继续发送一份完整 JSON，但增加可选元数据字段：

```json
{"device_profile":{"slot":2,"name":"音乐"},"profiles":[{"id":"default", ...}]}
```

旧桌面端不发送 `device_profile` 时，固件按当前活动槽位更新；不会自动覆盖其它槽位。新桌面端在“保存并同步”时明确指定槽位，固件回执中返回 `slot`、`active_profile` 和应用结果。

如果后续需要设备端复制/清空槽位，再单独定义命令，不把删除语义塞进普通配置覆盖路径。

## 运行时状态机

1. `Idle`：当前 profile 正常工作。
2. `Prepare`：锁住一次切换请求，暂缓第二次短按，防止重复提交。
3. `Validate`：读取目标槽位、校验 CRC、解析 JSON、检查硬件相关约束。
4. `Apply`：在主任务边界替换 `ConfigState`，同步旋钮轴、平台快捷键和音频配置。
5. `Commit`：确认应用成功后写 `active_slot`，清理 `pending_slot`。
6. `Failed`：恢复旧 `ConfigState` 和旧槽位，保留失败原因码，等待下一次用户输入。

切换期间不得让旋钮旋转事件进入旧配置和新配置的混合状态；旋转事件应暂存或丢弃并给出一次忙反馈。音乐播放切换时先停止旧会话，再由 `SpeakerOutput` 的唯一 I2S owner 应用新配置，不能新增并行 I2S 控制器。

## 反馈与可观测性

- LED：槽位 0/1/2/3 分别使用不同短脉冲次数；失败使用红色双闪（具体颜色沿用现有 LED 合同）。
- 状态 JSON：增加 `active_profile`、`profile_count`、`profile_switch`（`idle/applying/failed`）等短字段，并继续遵守 BLE 512 字节上限。
- 日志只输出槽位编号、结果码和长度，不输出 profile 文本、用户快捷键、SSID、密钥或设备唯一标识。

## 分阶段实现与验收

### 阶段 A：纯逻辑（已完成最小版本）

- 新增 `EncoderFunctionRing`，覆盖首尾循环、空环安全和单槽稳定。
- 默认 `EncoderPress` 动作改为 `function_cycle`；显式配置的 `scroll_axis_toggle` 仍兼容。
- 当前只接入“键盘/音乐”两个运行槽位，profile 多槽 NVS 和桌面端槽位管理仍待后续阶段。

### 阶段 B：固件运行时

- 接入 `ConfigState` 的候选配置应用和 `profiles_v1` NVS。
- 复用现有旋钮手势；短按只切 profile，3 秒长按仍进入配置模式。
- 增加 LED/状态反馈，并运行完整宿主测试与 ESP-IDF 5.5.5 构建。

### 阶段 C：桌面端对接

- Studio 增加槽位选择、命名、保存并同步、回执展示。
- 验证旧 Studio/旧 JSON 兼容：无 `device_profile` 时仍按旧逻辑工作。

### 阶段 D：实板验收

- 仅在身份复核和用户明确确认后烧录。
- 分别验证短按循环、空槽跳过、断电恢复、音乐/键盘切换、切换中快速连按和失败回滚。
- 构建成功、烧录成功、正常 HID 枚举和业务功能通过分别记录，不能互相替代。

## 暂不做的事项

- 不把旋钮按压映射成 BOOT、复位、擦除或整机恢复。
- 不改变 GPIO、分区、设备身份、USB/BLE 基础协议和 GPIO8 共享电源时序。
- 不让固件猜测桌面端配置文件路径，也不复制桌面端历史数据库或账号信息。
